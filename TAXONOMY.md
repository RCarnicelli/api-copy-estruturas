# Evidence-bearing taxonomy v1

Development branch/service only. Adds `swipes.taxonomy` JSONB without rewriting any legacy classification fields. Existing REST and five MCP signatures/envelopes remain unchanged; items add `taxonomy`. Existing exact/soft filters retain their semantics and category spellings.

Each attribute includes value, certainty (`observed`, `inferred`, `unknown`, `not_applicable`), application (`recommended`, `present`, `unknown`, `not_applicable`), evidence_origin and evidence. A source description is not original asset inspection. Frameworks, techniques and patterns are separate. Main offer and next-step offer are separate. Proof presence/status and claim verification are separate. No aggregate quality score, reranking or automatic curation.

Approved conservative snapshot: 25 IDs; 3 real-piece descriptions, 1 collection, 21 templates/frameworks/guidance. No retention or reactivation assigned. Template testimonials are recommended only. All distribution values unknown. Postcard platform not applicable; its performance claims are unverified and conflicting. Eight Sleep has no confirmed channel, CTA, paid distribution or premium-price argument. Collection remains available under existing retrieval behavior for compatibility.

`POST /taxonomy/apply` requires explicit `SWIPE_TAXONOMY_ENABLED=1` and the existing embedding-administration Bearer credential. Defaults to dry_run. Paid calls: zero. Actual apply runs idempotent schema migration, locks all relevant records, checks SHA256 fingerprints of unchanged legacy classification, then updates taxonomy atomically. Stale snapshots abort all enrichment. Snapshot is checked in for audit/review. No automatic backfill at startup. New records expose unknown taxonomy pending evidence-based enrichment; classifier prompts unchanged.

Semantic v2 applies only to enriched rows. Uses approved taxonomy values plus application/certainty, title, description, emotion, tone, hook, mechanism, CTA. Excludes raw navigation, URLs, legacy mixed categories/objectives/framework labels, hypothetical adaptations, administrative evidence text and proof-verification metadata. Strategic summary explicitly identifies unsupported performance claims. v1 remains supported for unenriched records. Metadata-only edits can mark dirty but matching semantic hash reuses vector without a provider call. Query cache hash stays v1 since query text/model/dimension did not change.

Model: text-embedding-3-small, 1536 dimensions; maximum 2048 tokens/document, batches 8, maximum 25 documents per execution, existing daily call caps and paid authentication retained. All 25 reviewed documents acquire materially changed meaning-bearing text, so 25 new document embeddings are expected; repeating unchanged backfill performs zero calls. Search remains exact cosine with existing AND structured filters; no ranking fusion or reranking.

Checks: legacy suite plus taxonomy snapshot, provenance, recommendation-vs-presence, unknown handling, evidence-only hash stability, semantic-change hash invalidation, stable query-cache identity, conservative lifecycle, separated offer/next step, framework/format distinction, stale-snapshot atomic rejection, administrative authorization. Live verification and exact five-query comparison recorded in TAXONOMY_VALIDATION.md after deployment.
