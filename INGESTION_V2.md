# Ingestion classifier v2

Controlled curation cycle 01 adds a narrow public Really Good Emails detail adapter alongside Swipefile. Discovery stays Swipefile-only; reviewed /emails/slug URLs share canonical deduplication, authentication, budgets and the same enrichment-before-embedding pipeline. RGE public HTML is parsed without executing scripts or following embedded URLs. See CURATED_CYCLE_01.md for source restrictions and live validation.

Development-only upgrade. Endpoint names, request shapes, default dry_run, ingestion Bearer credential, canonical URL deduplication, global ingestion lock, per-URL transaction lock, 3-attempt batch cap, 150-second scheduling deadline, per-item errors and no automatic retries remain unchanged. No bulk collection is authorized by deployment.

Sequence: pre-capture dedup -> bounded Crawl4AI capture -> one gpt-6-luna Responses call producing legacy fields AND complete taxonomy -> conservative contract validation -> one atomic PostgreSQL insert of legacy content plus taxonomy -> semantic v2 embedding for the saved ID only. Failure/incomplete classification means no insert and no embedding. Embedding failure leaves the enriched swipe persisted and pending; later backfill needs no reclassification.

Version names are intentionally separate: pipeline `swipe-classifier-v2`, approved taxonomy storage contract `swipe-taxonomy-v1`, semantic document text `swipe-semantic-v2`. The user-facing v2 upgrade does not require rewriting the existing 25 taxonomy objects or vectors.

Unknown is complete classification when evidence is insufficient. All 21 attributes are mandatory; record_type and strategic_summary must be identified. New classification validation enforces types/vocabularies, observed/inferred evidence origins, recommended/present proof and technique consistency, framework-vs-format separation and retention/reactivation customer context. Textual crawling cannot claim original_asset inspection or verified proof. Product pictured does not establish campaign authorship. Navigation, hypothetical adaptations and generated creative variations are excluded from classifier input when marked in Markdown. Full original content remains stored, not logged.

Legacy category labels and classifier output keys remain present. Read paths and the five MCP tools are unchanged. Saved ingestion results additionally include taxonomy_status, taxonomy_version and classifier_version. No reranking or search-algorithm change.

Cost limits: maximum 12000 source characters, 8000 input tokens and 6000 output tokens; exactly one classification attempt per candidate, no auto retry. `classification_usage` records model, token usage, attempt timestamp, provider_received and validated flags, never source text or secrets. Daily maximum 20 classification attempts (UTC DB day), reserved under a global transaction lock before provider calls; failed attempts consume the cap. Existing embedding daily limits, hash reuse, bounded chunks and authentication remain. Increasing output budget from 2000 is necessary for evidence-bearing taxonomy; input/output tokens are explicitly capped.

Schema migration adds only the classification usage table/index. Existing swipes remain untouched until an explicitly authorized single-piece test. Regression suite: 66 tests, including atomic taxonomy persistence, save-before-embedding ordering, missing/inconsistent taxonomy rejection, template-vs-executed proof, customer-context guards, Responses message selection after reasoning, input-token refusal, daily-call budget, no-paid dry-run and deduplication. Live single-piece validation is documented separately after execution.
